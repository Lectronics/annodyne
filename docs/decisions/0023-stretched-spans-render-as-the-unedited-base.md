# ADR-0023: Stretched TimeMap spans render as part of the unedited base

- **Date:** 2026-10-22
- **Status:** accepted 2026-10-22 with the owner's amendments below (decisions 2, 3, 3a, 5 and 7 are amended; the readings of the grid, of "whole numbers" and of one global tempo step were confirmed by the owner 2026-10-22)
- **Phase:** 5
- **Amends:** ADR-0008 §7 (a warp with slope != 1 renders from Phase 5, not Phase 6), ADR-0006 (`RenderResult` gains `repaired_notes`; the pristine base is `render_unedited`)

## Context
`build_time_map` stretches everything between two anchors: the edited note, unedited notes, gaps and the tail. `render_region` takes `read_through_map` as "the original" and refuses any slope != 1 span, so no timing edit that stretches can render. Design: `docs/design/phase5-stretch-render.md`.

## Decision
1. **The unedited base is `render_unedited`**: slope-1 warps and inserts exactly as `read_through_map`; slope != 1 warps through `stretch_span` (TD-PSOLA time scaling for voiced frames, power-complementary grains for the rest; pitch and timbre kept). "No edits, same audio" is unchanged for slope-1 spans and holds for stretches as "stretch only".
2. **Edited notes** (pitch, level, formant, ...) are rendered by the engine passed to `render_region` as today and blended over the base. A note whose only edits are timing edits is part of the base, not an edited note. A pitch/formant/level edit on a note whose zone meets a slope != 1 span returns `not_implemented` naming the note (routing engine: Phase 5 slice 3).
3. **Tail policy.** `TimeMapParams::tail {keep_length, shift}` (default `keep_length`, unchanged): `render_region` uses `shift`, so audio after the last edited anchor is shifted (slope 1), not squeezed to keep the file length; the output length changes by the net edit. Stretching is confined to the spans between edited anchors.
3a. **Whole-sample shifts.** `TimeMapParams::sample_rate` (default 0 = off) quantises the shift (output minus source time) of every anchor to a whole sample after the minimum-segment repair, so slope-1 spans stay whole-sample shifts; strictness by one-sample pushes; a push past a fixed end cancels the quantisation. `repaired_notes` is decided before rounding. `render_region` sets it; caller-supplied maps must satisfy the same.
4. **New targets** `core/synthesis/grain` (marks, fractional reader, grain overlap-add, extracted from PSOLA, output bit-identical, `-ffp-contract=off`) and `core/synthesis/stretch` (`stretch_span`), both layer 2. `render_unedited` lives in `core/render`.
5. **Cache:** a stretch invalidates every block after it (the key includes the map; `dirty_regions` already returns origin-to-end for timing). Accepted for now.
6. `RenderResult` gains `repaired_notes` and `stretched`; `RenderParams::stretch` is hashed into the cache key.
7. **CLAUDE.md rule 5 and `architecture.md`** ("output outside dirty regions equals the source") are read relative to `dirty_regions`, which already covers origin-to-end for a timing edit (ADR-0005 §16). Outside the stretched spans the output is the source shifted by whole samples, bit for bit; inside them it is the stretch. The audio-verifier's untouched-region check is defined against the shifted source. This is the owner's to confirm at acceptance; until the shift-first layout (ADR-0008 §4) a handle dragged across neighbours still stretches them.

## Alternatives considered
- **Stretch only the edited note's zone**: the map also stretches neighbours and gaps, so the base would still be undefined there. Rejected.
- **Interpolate slope-1 spans at fractional shifts**: not bit-exact, breaks rule 5 for the whole tail. Rejected for rounding anchors (an error of under one sample in the stretch ratio).
- **A `SynthesisEngine` for stretching**: it is not chosen per note and would have one caller. Rejected.

## Consequences
- ADR-0008 §7, `read_through_map` and `render.cpp` mention Phase 6 for stretching; they say Phase 5.
- The layout solver of ADR-0008 §4 (shift first) later reduces how much is stretched; it needs no change here.
- Vibrato rate changes with the stretch until `regenerate_pitch_curve` exists; plosive/sibilant protection until the segment weights (slice 2).

## Amendment 1 (owner, 2026-10-22): base clip, silent anchors, grid, local invalidation, whole-number stretch

Decisions 1, 4 and 6 stand. The rest read as follows; where this section and the text above differ, this section wins.

**2 (amended): the base clip.** The result of `render_unedited` is a named object, the **base clip**: the source after the timing edits (the TimeMap applied: slope-1 spans shifted, stretched spans through `stretch_span`, inserts and cuts), computed block by block. Timing edits belong to the base clip, not to the source audio, which is never touched (rule 1). Pitch, level and formant edits are applied on top of the base clip (an edited note is rendered by the engine and blended into it, as today). A pitch or level edit therefore never recomputes the base clip; a timing edit recomputes it only where its spans change (see 5). A note whose only edits are timing edits is part of the base clip (unchanged). "Base clip" is not the "clip" of `docs/design/clips-layers-and-groups.md` (a pasted virtual note): the base clip is the main layer's timing-resolved audio, and pasted clips are mixed on top of it.

**3 (amended): silent anchors, keep_length is the default.** The start and the end of the recording are fixed anchors, treated as silence: the output length equals the source length. `render_region` uses `TailPolicy::keep_length` by default (it passes `keep_length` instead of `shift`), and with a timeline the layout of ADR-0025 absorbs a change in the leading or trailing gap first, so the file length never changes. `TailPolicy::shift` stays available as an explicit option for callers who want the tail to move. Sequencing: while the layout (ADR-0025, slices 8c-8e) is not built, a stretch with no timeline would squeeze the tail through the stretcher, so the default is flipped in the same slice that lands `build_layout_map`; until then `render_region` keeps `shift`. A slope outside the stretch limits is still a named `not_implemented`, not a silent clamp.

**3a (amended): the shift grid.** Shifts (output minus source time of a marker) are no longer quantised to a single sample but to a **shift grid**: a step defined from the detected tempo as a fraction of a whole note, `step = division x 4 beats / tempo`, with `division` a parameter (the owner proposes 1/256 or 1/512; default 1/512, which is about 3.9 ms at 120 bpm and bounds the rounding error of a requested shift to half of that). The step is **normalised to a whole number of samples** at the render sample rate (`step_samples = max(1, round(step_seconds x rate))`), so every grid shift is a whole number of samples and the whole-sample rule of this ADR still holds exactly. Until the tempo analysis exists (Phase 8 `analysis/rhythm`) the grid uses a fixed fallback tempo of 120 bpm; tempo-curve support is later (one global step from the median beat period). `TimeMapParams::sample_rate` is replaced by `TimeMapParams::shift_grid {step_samples}` (0 = off, 1 = whole samples, the old behaviour); the repair order is unchanged (after `enforce_min_segments`, strictness by one grid step, fixed-end fallback).

**5 (amended): a timing edit invalidates only what it changes.** The cache key no longer hashes the whole TimeMap. It hashes **the spans that intersect the block and the zones it reads** (plus the recording's source length). Two blocks that see the same spans have the same key whatever happens elsewhere in the file. `dirty_regions` returns, for a timing change, the **intervals whose spans differ** between the old and the new map (computed from the two maps, plus the guard margin), not origin-to-end. With the pinned-marker layout (ADR-0025) a marker move changes only the two intervals next to it, so every block outside them is reused. The Flex builder in `stretch` mode and `shift` still change everything after the edit (the shift moves all later spans); that is a property of those modes, not of the cache.

**7 (amended): rule 5 and whole numbers.** Rule 5 ("bit-identical outside edited regions") now reads against the precise dirty intervals of 5: every sample outside them is the source, shifted by a whole number of grid steps, bit for bit. **Stretched spans use whole numbers too**: both ends of a span lie on whole samples on both axes, so a stretch maps N source samples to M output samples (integers), and with every marker's shift on the grid, M - N is a whole number of grid steps. The marker's source position is rounded to the nearest whole sample for this (at most half a sample, 10 microseconds at 48 kHz). `stretch_span` takes integer sample ends and its slope is the exact ratio M/N.

Consequences of the amendment: `TailPolicy` default and the tail logic in `render_region` change with the layout slice; `RenderKeyInputs` hashes a span subset; `dirty_regions` takes the old and the new maps (or the two edit lists and builds both); `build_time_map` quantises through the shift grid; the existing tests of `sample_rate` become `shift_grid {1}` tests; new tests for the grid normalisation (step in samples at 44.1, 48 and 96 kHz and at several tempi), for block-local keys (a far-away marker move leaves a block's key unchanged) and for integer span lengths.
