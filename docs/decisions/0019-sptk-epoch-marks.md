# ADR-0019: SPTK as the source of pitch marks (REAPER epochs)

- **Date:** 2026-10-21
- **Status:** proposed 2026-10-21 (owner wants SPTK integrated, not in Phase 4; structure review round 1 answered in this revision; round 2 and owner acceptance pending). The dependency enters the build only when the Decision 6 trial passes.
- **Phase:** decided in 4, implemented in 6 (first slice)

## Context
`PsolaEngine` makes its own analysis marks inside the engine from the stored pitch curve (ADR-0016). The first version snapped each mark to the tallest sample. On real voices that jumps between waveform features and produced audible hiccups (owner listening, 2026-10-21). Replacing the snap by waveform matching against the previous period, with fractional marks, brought the measured cycle-to-cycle jump on 12 real-voice scenarios (4 Vocadito tracks, 3 shifts, 1 note per scenario; tracks 13, 28, 37, 4) to the source's level. Numbers and method: `docs/design/phase4-pitch-edit.md`, "Stage 9b".

The owner's research report `docs/design/pitch-marks-integration.md` compares SPTK, REAPER and Praat as pitch-mark sources. Its findings come from a synthetic 220 Hz vowel only: SPTK's REAPER wrapper gave epochs identical to the REAPER command-line tool; marks fall on whole samples; unsmoothed marks kept vibrato rate and extent in a PSOLA bench. Real singing, breathy and rough voices and high pitches were not tested, and the report notes REAPER's built-in search range is 40-500 Hz. SPTK also bundles WORLD (Harvest, DIO, CheapTrick, D4C), SWIPE', RAPT and resamplers. ADR-0018 plans a second independent tracker for the octave flag in Phase 13 and builds no WORLD/STRAIGHT path; the small-shift routing idea comes from `psola-vibrato-hiccups.md` section 6.

The owner decided (2026-10-21) to integrate SPTK, not in Phase 4. Licensing is the owner's to handle (ADR-0014 pattern).

## Decision
1. **Dependency and wrapper target.** SPTK (pinned to one commit, library only: `SPTK_BUILD_COMMANDS=OFF`, `SPTK_INSTALL=OFF`, `SPTK_INSTALL_DRAW_COMMANDS=OFF`) is wrapped in one target `anno_sptk` (INTERFACE/STATIC, `ANNO_HELPER TRUE`, like `anno_c4dm_pyin` in ADR-0014). SPTK's four include directories (`include`, `third_party`, `third_party/REAPER`, `third_party/WORLD`) are PRIVATE to the wrapper, never propagated. Fetched-and-pinned or vendored is decided in the Phase 6 design note once the trial has a CI build; both must build offline from a cache. Praat is **not** adopted (30-minute build, no library target, mixed licence headers); REAPER is used only through SPTK.
2. **Layer placement.** `core/analysis/pitch_marks` (layer 1) links `anno_core_types` and, privately, `anno_sptk`. `cmake/AnnoLayers.cmake` gets one external-allowlist clause (folder `core/analysis/pitch_marks`, dependency `anno_sptk`), with fixtures `allow_pitch_marks_sptk` (PASS) and deny fixtures for `core/dsp`, `core/analysis/pitch` and `core/synthesis/psola` (R6). `PsolaEngine` (layer 2) links nothing new: it reads the marks through `core/types`. Only the analysis orchestrator calls `analyse_pitch_marks`.
3. **Contract.**
   ```cpp
   struct PitchMarksParams {
       Hz f0_floor{60.0};              // REAPER lower F0, > 10 Hz
       Hz f0_ceiling{500.0};           // upper F0, < sample_rate / 2; see the 880 Hz pre-step (6)
       double unvoiced_cost = 0.9;     // REAPER voicing threshold, dimensionless, provisional
   };
   struct PitchMarkTrack { std::vector<SourceTime> marks; };   // sorted, strictly increasing, voiced epochs only
   [[nodiscard]] Result<PitchMarkTrack> analyse_pitch_marks(std::span<const float> mono, Hz sample_rate, const PitchMarksParams&);
   ```
   Marks are REAPER's voiced epochs only (no voiced flag: gaps between marks are unvoiced stretches; the analysis makes no voicing decision of its own beyond REAPER's), unsmoothed. The wrapper scales and clips floats to the int16 range (SPTK truncates doubles to int16, undefined out of range). Errors: `invalid_argument` for an empty span, a non-finite sample, a rate outside 6000..98000 Hz (no resampling; a 192 kHz take is rejected until a design note adds one), floor <= 10 Hz, ceiling <= floor or >= rate/2, or `IsValid()` false; `internal_error` if SPTK's `Get` returns false. Zero epochs is a valid empty track. The orchestrator downmixes to mono; the function never sees channels. Pure, thread-safe (fresh tracker per call), allocates, not real-time safe, whole-take and offline with no cancellation; the report puts it at about 0.35x real time on 2 cores (1.4 s for 4 s), so the orchestrator runs it on a background thread in the analysis cache and the Phase 6 design note sets a budget and a cancel path.
4. **How the marks reach the engine (core contract change).** Engines receive only a `Note` (`SynthesisEngine::render_note(src, note, eff, time_map, out_range)`), so the marks are a **`Note` field**, `std::vector<SourceTime> pitch_marks`, like `harmonics`, `noise` and `envelope`. The orchestrator fills it from the take-level `PitchMarkTrack` with the marks inside `[note.source_start - k_pitch_mark_margin, note.source_end + k_pitch_mark_margin]`, `k_pitch_mark_margin = 0.15 s`, defined in `core/types/note.h` (provisional: `PsolaEngine`'s edge margin `k_margin_s` is 0.1 s, plus one maximum period of 25 ms at 40 Hz, plus slack; independent of `RenderParams::crossfade_length`, which is 10 ms, because `validate(Note)` is pure). `validate(Note)` gains: sorted strictly increasing, finite, inside that window; an empty vector is valid (no marks). `AnalysisResult` keeps the take-level track only if a later tool needs it; this ADR does not add it. Overrides spec section 3 `Note` and the architecture-spec `AnalysisResult` field list (the spec lists no pitch marks). The analysis fingerprint and version change with the field.
5. **Engine use and caching.** `PsolaEngineParams` gains `mark_source` (`own` | `pitch_marks`, enum) and `mark_max_gap{0.02 s}` (the engine's own provisional threshold: Praat's speech value for a gap between marks; it is not an analysis parameter). Voicing stays with the frame classes (ADR-0017): they decide which frames are shifted, and marks inside non-shifted frames are ignored. For a shifted run with `pitch_marks`, the analysis marks are the note's marks while consecutive marks are at most `mark_max_gap` apart; over a stretch with no mark or a larger gap, the run uses the engine's own waveform-matching marks, seeded from the nearest mark, and the handover switches at a mark with no blend (grains are placed on the synthesis marks, so only the list of grain sources changes). The window of decision 4 extends past the note by more than the engine margin, so clipping creates no artificial gap inside the engine's span. `mark_source` and `mark_max_gap` are in `settings_key()`, and the engine `version()` is bumped when the default changes. The `own` path is permanent (the fallback and the default until the trial passes), so it is not dead code. Tests: a note with marks on part of its span (handover at a mark, no click), a note with no marks, marks inside a non-shifted class.
6. **A/B trial gates adoption (objective, thresholds provisional per ADR-0018 decision 1).** The dependency is not merged into the main build's CMake and `mark_source` stays `own` until the trial passes; the trial runs on a branch.
   - *Pre-step:* confirm on a synthetic 880 Hz voice that the wrapper honours `f0_ceiling` 880 Hz. If REAPER cannot go above its internal 500 Hz cap, record that, and scope REAPER marks to notes below it (the gap rule above falls back to `own` marks).
   - *Corpus:* the 12 `phase4-real` scenarios, plus the Phase 6 additions the owner supplies or approves: at least 6 notes marked rough, 6 marked breathy (hand labels from the owner or a labelled subset; none exists in the repo today), and a synthetic set at 440, 660 and 880 Hz.
   - *Metrics, per scenario, `own` against `pitch_marks`:* cycle-jump measure (max over the note) no worse than the source's max plus 0.02; vibrato rate within 0.2 Hz of the source; pitch round trip within `PitchCheckParams::pitch_roundtrip` (3 cents); click detector zero new detections; null and untouched checks pass.
   - *Prerequisites that do not exist yet:* the cycle-jump measure ported from `scripts/phase4_cycle_jump.py` into `cli/checks/pitch_checks` as a report row (it is an offline script today); rough and breathy labels (owner); 440, 660 and 880 Hz sources (an addition to `scripts/make_phase4_sources.py`).
   - *Pass:* on every scenario `pitch_marks` meets each bound that `own` meets (`own` already misses the 0.2 Hz vibrato bound on several real voices, within about 1 Hz; there the rule is no worse than `own`), and on at least 4 of the rough/breathy notes its cycle-jump 90th percentile is lower than `own`'s. Otherwise REAPER marks are not adopted and the dependency is dropped from the main build (Decision 7 items on other uses are then re-decided).
   - *Ties and subjective:* a human listening A/B on the same scenarios decides anything the bounds do not (docs/AUDIO_VERIFICATION.md, listening sheet), and the result is recorded in the Phase 6 design note.
   - *Branch:* `Note::pitch_marks`, its `validate`, the fingerprint bump, `analyse_pitch_marks`, the `anno_sptk` target and `mark_source` all live on the trial branch and merge together only on a pass, so the fingerprint is re-baselined once and only for an adopted dependency.
   - *Ordering:* the trial needs PSOLA to still be a candidate default. If ADR-0016's default-engine choice after listening gate #1 drops PSOLA, the trial and `analysis/pitch_marks` are re-planned (the marks still serve vibrato and pitch-modulation tools).
7. **Other uses (not decided).** Harvest or SWIPE' as the second tracker for the octave flag, WORLD for small shifts, and SPTK's resamplers. ADR-0018 is amended (below) so Phase 6 may do the octave-flag tracker from SPTK if the trial shows SPTK is worth keeping; the Phase 13 neural estimator stays as the alternative.

## Alternatives considered
- Keep engine-internal marks only: no dependency and at the source's jump level on the tested scenarios. Con: marks depend on the stored pitch curve and a waveform match; untested on rough or breathy notes; no independent voicing decision.
- Vendor REAPER only: smaller, but archived, a stale header (the documented calling sequence does not exist), and no second tracker.
- Praat: reference PSOLA code, but a heavy build, no install target, undocumented start-up calls, mixed licence headers.
- Build it now in Phase 4: the listening gate is open; a new third-party dependency, a new `Note` field and a new analysis stage would reopen the design and the fingerprint.
- Change `render_note` to pass the take's marks: worse, it breaks every engine and the contract for one engine's input.

## Consequences
- Phase 6: new third-party dependency (after the trial), `core/analysis/pitch_marks`, `Note::pitch_marks`, `validate(Note)` clause, fingerprint/version bump (re-baseline fixtures as with partials), `PsolaEngine` `mark_source`, ROADMAP Phase 6 items.
- CI builds SPTK (52 s on 2 cores in the report). Three configure/build checks are required before merge: (a) include-directory and symbol collisions with JUCE and the ARA SDK (SPTK links SpeexDSP, libsamplerate, r8brain, WORLD and Snack code; use a symbol-collision test on the host binaries), (b) SPTK compiled with `-ffp-contract=off` (ADR-0014) so analysis fingerprints and golden hashes stay deterministic, (c) offline/cache reproducibility of the pinned source.
- Licence: the owner decides. Facts for that decision: SPTK and REAPER are Apache-2.0, compatible with GPLv3 but not GPL-2.0-only, so the combined work with ADR-0014's GPL-2.0-or-later code is effectively GPLv3-or-later (as ADR-0014 already notes for JUCE); `THIRD_PARTY.md` gains entries for SPTK, REAPER and the bundled WORLD, SWIPE', Snack, SpeexDSP, libsamplerate and r8brain.
- Tests: `analyse_pitch_marks` on a synthetic impulse-train vowel (marks within one sample of the known closure instants up to a constant offset, none on silence, none or few on noise, rate and parameter errors), `Note::pitch_marks` validate cases, engine `mark_source` cache-key test.

## Spec updates
Spec section 3 (`Note`): this ADR adds `Note::pitch_marks`. `AnalysisResult` is unchanged. No other spec section changes.

## Amendment to ADR-0018 (2026-10-21)
The row "Two independent pitch trackers for the octave flag (neural estimator as second tracker)" stays in Phase 13 and is conditionally movable to Phase 6 if ADR-0019's trial keeps SPTK and a Harvest/SWIPE' tracker passes the octave-error check (under 2 % on the labelled set); the neural estimator remains the alternative. No other row changes.
