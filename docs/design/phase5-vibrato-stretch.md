# Phase 5: vibrato-preserving stretch (design note)

Status: draft for structure review, 2026-10-23. Amends ADR-0023 (stretch render). Owner requirement (2026-10-23, after listening to `layout_a_*`): stretching or squishing a note must not change its vibrato rate by more than 0.5 Hz, from any edit or chain of edits; depth should stay as close to the source as possible (unless the edit is a vibrato control).

## Problem (measured)
`stretch_span` re-times the whole pitch contour, so the vibrato rate scales with 1/slope. Measured on `gap_fricative.wav` (source vibrato 5.7 Hz, 37 cents; DFT of the f0 trace, drift removed): slope 0.6 gives 9.1 Hz, slope 1.4 gives 3.9 Hz, slope 2.0 gives 3.0 Hz. Depth stays 35-41 cents; a slower rate at the same depth is what sounds like "more depth". The README already listed this as a known limit.

## Method
Per voiced run, the output pitch contour is `slow(tau(p)) + vib(p)`:
- `slow` = `pitch_center + pitch_drift` of the note frames, re-timed as today (it is the part that should stretch with the note).
- `vib` = `pitch_mod`, **regenerated** at the source rate instead of re-timed.
- The audio grains are still taken from the analysis mark nearest the source time `tau(p)` (so the timbre, formants and noise stay those of the source); only the *synthesis spacing* follows the new contour: the period at output position `p` is the period of `slow + vib`. This is TD-PSOLA pitch scaling by `r(p) = f_out(p) / f_src(tau(p))`; the vibrato terms differ by at most `2 * depth` (about 75 cents, 4 %), well inside TD-PSOLA's range.

**Vibrato model.** Complex demodulation of `pitch_mod` at the run's vibrato rate `f_v` (DFT peak in 3..9 Hz over the run's source interval; none found, or depth under 5 cents: no regeneration, today's behaviour). A Hann window of 1.5 cycles gives amplitude `A(sigma)` and unwrapped phase `phi(sigma)` per frame. Output:

    vib(p) = A(tau(p)) * cos(Phi(p)),   Phi(p) = phi(tau(begin)) + (1 + eps) * integral over [begin, p] of 2*pi*f_v(tau(q)) dq

so the rate is the source's local rate and the amplitude is the source's, played at slope 1. `Phi` starts on the source phase at the run start.

**Joins.** Where the run continues voiced into the neighbouring slope-1 audio (`join_begin`, `join_end`: the source frame just outside the span is voiced) the vibrato phase must agree there or the pitch steps. At the begin it does (`Phi` starts on `phi(tau)`). At the end `eps` is chosen so `Phi(end)` equals `phi(tau(end))` modulo `2 pi`, rounding to the nearest whole cycle: the rate then differs from the source by at most `0.5 / L` Hz for a run of `L` seconds (under 0.5 Hz for `L >= 1 s`). When the run ends inside the span (a note end: silence follows), `eps = 0` and the rate is exactly the source's. A run shorter than one second with a join at both ends may exceed 0.5 Hz by up to `0.5/L - 0.5` Hz; this is reported in the README as the limit, not hidden.

**Determinism and range independence.** The vibrato clock is a function of the run (its begin, end, the notes' frames) only, never of the requested output range; a run is rendered whole per call as today. Same inputs, same samples.

**Chains of edits.** Every edit is a map from the source, so the vibrato is regenerated from the source's `pitch_mod` each time; there is no accumulation.

## Interface
- `core/synthesis/stretch/detail/vibrato.{h,cpp}` (new): `struct VibratoSource` (frame times in source samples, `pitch_mod` cents), `class VibratoClock` built from it and the run (`SpanGeometry`, `begin`, `end`, `join_begin`, `join_end`), method `double cents(double out_position) const` (0 when not present), `bool present() const`, `double rate_change_hz() const` (the `eps * f_v` actually applied, for tests). Pure; thread-safe; not real-time safe.
- `pitch_points` gains a sibling `slow_points` (centre + drift) and `vibrato_source`; `PeriodCurve` for the *analysis* stays on the full contour.
- `synthesise_voiced_run` takes the output pitch as a function `period_out(out_position)` built from `slow` and the clock; the first and last synthesis marks still sit on analysis marks.
- `StretchParams::preserve_vibrato` (enum `VibratoMode {preserve, retime}`, default `preserve`) so tests and the golden path can compare; hashed through `StretchParams` where it is already hashed.

## Errors and limits
No new error. Mono only, as before. No vibrato found: unchanged output (bit-identical to the old path). Real vibrato is not exactly sinusoidal and its amplitude coupling (tremolo) is not regenerated: the model carries the pitch only; the amplitude and timbre come from the grains. Plosives and the noise path are unchanged.

## Tests (first)
1. Synthetic voice with 5.5 Hz, 40 cents vibrato: after slope 0.6, 1.4, 2.0 and 3.0 the output's analysed vibrato rate is within 0.5 Hz of 5.5 and depth within 25 % (run at least 1 s long).
2. `VibratoClock`: with slope 1 the clock reproduces `pitch_mod` (within a few cents); `rate_change_hz` is 0 with no join at the end and at most `0.5/L` with one; continuity of `Phi` at the begin.
3. No vibrato (steady tone): output bit-identical between `preserve` and `retime`.
4. Chain: stretch by 1.5 then the same warp inverse composes through the source only (render of map `m` is independent of how it was reached); same samples for two ranges of one run.
5. Existing stretch tests with `retime`; the golden/audio scenarios re-measured (rate and depth reported in the audition INDEX).

## Verification
`audio-verifier` re-runs the four layout scenarios and reports the vibrato rate and depth of source and edited (script: DFT of the f0 trace). Human listening remains required; the objective bound is 0.5 Hz.

## Revision 1 (after structure review, 2026-10-23): these decisions replace the text above where they differ
1. **Cache key and ADR.** `enum class VibratoMode : std::uint8_t { preserve, retime }`, `StretchParams::vibrato` (default `preserve`), validated by `check_stretch_params`. `render_key` hashes it by hand (`put(Writer&, const StretchParams*)`), `k_key_format_version` 5 -> 6 (the default output changes), with a key test that flips the field. ADR-0023 amendment 3 records the public type, the default and the version.
2. **Supersedes `regenerate_pitch_curve`** (note-stretching.md section 4, `analysis::VibratoModel`, `max_rate_adjust` 3 %) for the stretch render: that design regenerated a whole pitch curve in analysis; this one only needs a phase-continuous vibrato term at the source rate, inside the synthesis spacing, and its bound is the owner's 0.5 Hz, not 3 %. `analysis::VibratoModel` is not used (it does not exist as code); `perceived_pitch`'s `vibrato_period` is not reused (it is a zero-crossing estimate for pitch perception, 1 cycle windows). The README "known limit" and ADR-0023 consequence "vibrato rate changes ... until `regenerate_pitch_curve` exists" are amended.
3. **One rate per run.** `f_v` is a single value per run: the peak of a Hann-windowed single-frequency DFT of `pitch_mod` over the run's source interval, scanned 3.0..9.0 Hz in 0.05 Hz steps with parabolic refinement (no FFT, no core/dsp). `phi(sigma)` is the **total** unwrapped phase, `2*pi*f_v*sigma + arg z(sigma)`, where `z` is the complex demodulation at `f_v` over a Hann window of 1.5 cycles computed on the actual frame positions (frames are not uniform across notes). `A = |z|`. The output phase is `Phi(p) = phi(tau(begin)) + 2*pi*f_v*(1 + eps)*(p - begin)/rate`, i.e. the rate is `f_v(1+eps)`, not the local rate; the 0.5 Hz bound is therefore measured against `f_v` (and the verifier reports the source's own spread). Drift of the source rate is carried by `arg z` only through the begin phase and the `tau`-re-timed amplitude.
4. **Run bounds and joins.** The clock is built from the true `Run` (`run.begin`, `run.end`), never the halo-padded interval; the DFT/demodulation interval is the run's source interval `[tau(run.begin), tau(run.end)]` clipped to the notes' frames, so neither the halo nor `wanted` enters. `join_begin` = the run starts at `g.first` and the source frame at `tau(g.first) - one sample` is voiced and finite (looked up in the analysis, not the span-local indicator); `join_end` likewise at `g.last`. Chained stretched spans each start on source phase and end on source phase modulo `2*pi`, so they stay consistent at their shared boundary. A run that starts inside the span (after silence or noise) begins at `phi(tau(begin))` and needs no join.
5. **Edges of A and phi.** Within 0.75 cycle of a run edge the demodulation window is truncated; `A` and `arg z` there hold the value at 0.75 cycle in (they are not extrapolated).
6. **End rounding and the 0.5 Hz bound.** With a join at the end, `eps` rounds `Phi(end)` to the nearest whole cycle of `phi(tau(end))`; `|rate change| <= 0.5 / L_out` Hz, `L_out` the run's output length in seconds. For `L_out >= 1 s` that is within the owner's 0.5 Hz. A run shorter than 1 s output seconds with a join at its end can exceed it (up to `0.5/L_out` Hz); this is a stated limit, the audio-verifier reports the measured value, and the owner decides whether to relax the join in that case (fade the vibrato depth at the join) before the phase is closed. Without a join at the end `eps = 0` and the rate is exactly `f_v`. The spacing rescale in `synthesis_positions` (last position on `p_last`) is inside this budget and tested.
7. **Interface.** `struct OutputPitch { const grain::PeriodCurve& slow; const VibratoClock* clock; double rate_hz; }` with `double period_samples(double out_position) const`; `synthesise_voiced_run(x, analysis_period, output_pitch, geometry, begin, end)`; the analysis marks and the grains stay as today (analysis period, grain `before`/`after` from the marks); `r(p) = output period / analysis period` enters only through the synthesis spacing (classic TD-PSOLA), `Grain::output_period` is the output period at the mark. `class VibratoClock` with `static std::optional<VibratoClock> make(const VibratoSource&, const SpanGeometry&, Run, bool join_begin, bool join_end)`; empty means "no vibrato to preserve" (rate outside 3..9 Hz, depth under 5 cents, fewer than 2 cycles): the old path, bit-identical. `ClockInfo {double f_v_hz, depth_cents, rate_change_hz}` on the clock for tests. `VibratoSource` owns copies of `(source sample position, cents)` pairs (like `CentsPoint`). Constants (`k_vibrato_min_hz` 3, `k_vibrato_max_hz` 9, `k_vibrato_min_depth_cents` 5, `k_demod_cycles` 1.5) live in the detail header. Kernel code in samples, as `geometry.h` (ADR-0003). Files: `detail/vibrato.{h,cpp}` and `detail/pitch_extract.{h,cpp}` (the pitch extraction moves out of `class_map`).
8. **Downstream pitch edits (known limit).** Pitch, formant and `mod_scale` edits on a note in a stretched span still read the analysis re-timed onto the output axis, which carries the old (re-timed) vibrato rate; for such a note the base clip's vibrato is the regenerated one but the engine's contour is not. Recorded as a known limit in ADR-0023 amendment 3; the vibrato tools (Phase 6) will need the regenerated contour exposed.
9. **Cross-platform.** libm `sin/cos` differ across platforms; "same inputs, same samples" holds per platform, as for `equal_power_gains`.
